System map

How Clothza works,
end to end.

Three layers, one database, zero servers of our own. This is the whole machine — what runs where, who may touch what, and which pieces are already real.

01 — The stack

Where the code runs

Browser

React SPA. Holds the catalogue in memory, keeps the cart and theme in localStorage, and talks straight to Supabase over HTTPS. No server of ours in between.

Cloudflare Worker

Serves ./dist at clothza.tech. Any unknown path returns index.html at 200 so React Router handles deep links like /lookbooks.

Supabase

Postgres (11 tables), Auth (email + password), Storage (clothza-media). 35 row-level policies decide every read and write.

Android APK

The same dist wrapped by Capacitor. Signed release build, minSdk 24, package com.clothza.app.

04 — Access

Three roles, enforced twice

CapabilityCustomerShop ownerAdmin
Browse, cart, favourites, checkout✓✓✓
Create and edit own store—✓✓
List and stock own products—✓✓
See own orders and messages—✓✓
See every store, user and order——✓
Change anyone's role——✓

Enforced in the UI (route guards), and again in Postgres (RLS + a trigger that rejects role changes unless the caller is already admin). The second layer is the one that matters: a customer cannot promote themselves by calling the API directly.

06 — Status

What is real today

Working

  • Accounts, roles, sessions, route guards
  • Store create & edit, image uploads
  • Product add / edit / delete
  • Favourites, reviews, orders → Postgres
  • Domain, TLS, deep links, dark mode
  • Android APK, signed

Not yet

  • Messages and coupons — memory only, vanish on refresh
  • Seller Orders tab reads memory, not the table
  • No variant stock grid (size × colour × stock)
  • Payments: UI only, no gateway or webhook
  • No realtime updates between devices
  • Email delivery needs custom SMTP
